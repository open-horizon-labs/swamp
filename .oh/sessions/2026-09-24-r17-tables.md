## What was done

All Arrow in `crates/core/src/growth/columns.rs`, following the
existing `Stored*Row` + `write_*_rows`/`read_*_rows` pattern.
`crates/core/src/growth.rs` owns the domain conversions and the
scope-wide replace-wholesale write; `crates/core/src/report.rs` wires
the write (inside `observe_scope`, same gate as the snapshot and R15/
R16's tables) and the read (`report_scope_from_store`, last, after the
projects/units/nested-artifact/evidence rebuilds so the by-type project
recount below sees the final project list).

1. **`coverage.parquet`** -- one row per scope-wide observation's
   per-root coverage outcome. `class = "project"` for a walked scan
   root's `coverage::RootCoverage`; `class = "detector"` for an
   authorized unit root's own `coverage::UnitRootCoverage` (its FSEvents-
   replay answer). `status` stores the bare `RegionStatus`/event-covered
   tag (`region_status_tag`), never `RegionStatus::label()`'s formatted
   string (`"partial (...)"`) -- the reason text lives in its own
   nullable column, so status is a stable round-trip key. `cursor_family`
   records which `FsEventsState` anchor answered this row (`walk` for a
   project root, `unit_root` for a detector root) -- CHUNK_R17's literal
   column name; nothing downstream reads it yet. Replaces
   `ReportSnapshot.coverage_json` entirely: unlike the R16 unit/nested-
   artifact tables, `RootCoverage`'s fields are all typed columns here,
   so there is no not-yet-migrated remainder to overlay from the old
   cell, and the cell is simply gone (the schema has three columns:
   `scope_key`, `observed_at`, `report_json`).
2. **`series.parquet`** -- one row per `(series_key, bucket_index)` from
   `Report.series_by_key`, plus `Report.total_series` under the reserved
   key `columns::TOTAL_SERIES_KEY` ("`__total__`", never a real entity
   key). `window_secs`/`observed_at` are denormalized onto every row.
3. **`summary.parquet`** -- `Summary`'s overview counts
   (`metric = "overview"`, `key` = `projects`/`worktrees`/`artifacts`,
   `count`) and by-type totals (`metric = "by_type"`, `key` = ecosystem
   tag, `bytes`/`growth`/`count`), plus `Reconciliation`'s six scalars
   (`metric = "reconciliation"`, one row per named field, `du_total`'s
   row omitted when `None`). A `TypeSummary`'s `projects` count is *not*
   stored -- CHUNK_R17's column list for this table is `(metric, key,
   bytes, growth, count)`, and storing a project *count per tag* would
   need a second count column or a second metric; instead
   `rebuild_summary_from_tables` recounts it live from the already-
   rebuilt project list (the same source `report::summarize` itself
   counts from), which is why the rebuild function must run after
   `rebuild_projects_from_tables`.
4. **`notes.parquet`** -- `Report.notes`, one row per note, `seq` keeps
   order.
5. **`topology.parquet`** replaces the per-volume `topology.json`
   (`growth::StoredWorktree`'s fields, unchanged: `worktree_id`,
   `project_id`, `project_name`, `path`, `kind`, `remote_url`), plus
   `device` (from this volume's own `fsevents.json` walk anchor,
   nullable) and `observed_at`, matching CHUNK_R17's column list. This is
   the incremental walk's own topology-comparison sidecar
   (`growth::compute_unconfirmed_worktrees`/`apply_incremental`), not an
   input to `report_scope_from_store` -- it was already independent of
   `report_rows.parquet`/`last_report-*.json.zst` before this slice.
   `crate::fs_gate::store::JsonFile::Topology` (and its match arms) are
   deleted -- nothing constructs it any more.
6. `growth::write_report_snapshot` now clears `Report.notes`/`.summary`/
   `.reconciliation`/`.series_by_key`/`.total_series`/
   `.series_window_secs` to their defaults before serializing
   (`slim_report_for_snapshot_json`) -- those fields are rebuilt from the
   four tables above on every read, so keeping them in `report_json` too
   was silent duplication, not a cache of what the JSON already said.

`observe_scope` writes all four scope-wide tables from
`observation.coverage`/`.unit_root_coverage` and
`observation.merged`'s already-computed `series_by_key`/`total_series`/
`series_window_secs`/`summary`/`reconciliation`/`notes` -- no second
pass. `topology.parquet` was already written independently by
`ObservationCheckpoint::commit` (unchanged call site, just a different
file format underneath `write_topology`).

## Deviations from CHUNK_R17's literal text (each one disclosed, not
silently narrowed -- the brief's rule: implement the requirement as far
as it is real work, state the concern, let the user decide)

CHUNK_R17 says: "Delete `ReportSnapshot` and `report_rows.parquet`
entirely: `report_scope_from_store` assembles the whole `Report` from
tables," and "Delete... `last_report-*.json.zst` and whatever wrote it."
**Neither was done.** Both are more than this slice's four named tables
plus `topology.parquet`, and I did not want to either fake the
requirement (relabel a partial migration as complete) or silently
narrow scope without saying so. Concretely, what full deletion would
still need:

- `Report.root`, `.unowned`, `.dirs_by_worktree`, `.files_by_worktree`,
  `.schedule_line`, `.github_enrichment` have no table today.
  `dirs_by_worktree`/`files_by_worktree` are not optional in practice --
  `cli/schedule.rs`'s `cmd_observe` always passes `include_dirs: true`
  ("`report`/the TUI need the dir rows stored too") -- so this is a real
  table (or a rebuild from the existing per-volume `dirs.parquet`/
  `files.parquet` current tables plus a worktree-id-to-root join) with
  its own design, not a one-line addition. `unowned` would need a new
  scope-wide aggregation over every root's own `unowned.parquet`
  (mirroring `artifact_table_facts_for_roots`'s pattern, but `unowned`
  rows have no natural single-root partition key the way artifacts do,
  since `path_or_object` is already scope-relative). `root` I *did* find
  a real, cheap source for -- the first coverage row (in scope-root
  order) whose `RegionStatus::was_observed()`, which is exactly what
  `report::merge_root_report_into` would have set -- and
  `rebuild_coverage_from_tables` now sets `snapshot.report.root` from it
  when coverage rows exist. `reconciliation` is also now fully
  reconstructed (folded into `summary.parquet`, see above) -- it was not
  in CHUNK_R17's four-table list by name, but its scalars fit the
  `summary.parquet` shape exactly and it is a `Report` field the JSON
  cell no longer needs to carry, so I took it.
- `last_report-*.json.zst` (`growth::write_last_report`/`load_last_report`)
  is read by `consumers/signals.rs` (previous git signals: dirty/
  unpushed/locked/idle, to age rather than recompute them for a worktree
  FSEvents did not report as changed) and `consumers/cargo.rs` (previous
  `nested_artifacts` + `observed_at`, for the build-adapter replay
  cache) at *per-root* incremental-walk time -- a lower-level, different
  need than the scope-wide `ReportSnapshot` this session's tables cover.
  I looked for whether `worktrees.parquet`/`worktree_facts.parquet` (R15)
  could already answer `signals.rs`'s need instead: they can carry the
  values, but they are keyed by `scope_key`, and `signals.rs`/`cargo.rs`
  run inside `report_full_mode_scoped_tracked`, which can be invoked for
  a root under a scope composition that never wrote that exact
  `scope_key` (an explicit single-root CLI call, a different detector
  configuration). Reusing them correctly needs a lookup keyed by
  worktree identity across *any* previously-observed scope, not the
  exact-key filter every other rebuild here uses -- real design work, not
  a rename. Left for a follow-up slice; both files are named explicitly
  above so the next worker does not have to rediscover this.

I want to flag this concern to the user directly, per the brief's rule
3: CHUNK_R17's literal instruction was "delete report_rows.parquet
entirely" and I did not do that. I implemented what I could verify was
real, tested, byte-identical work (the four named tables plus
`topology.parquet`, with the JSON cell shrunk to only what genuinely has
no table yet) and left the rest named and reasoned about rather than
narrowing silently or mislabeling a partial migration as the literal
ask.

## A mistake caught by the existing tests, not new ones

My first pass removed `coverage_json`/`external_units_json`/
`agent_units_json`/`store_interiors_json` from `StoredReportSnapshotRow`
together, reasoning that R16 already tabled the latter three so their
JSON cells were vestigial. `units_nested_evidence_tables.rs` immediately
failed: `rebuild_units_from_tables`/`agent_unit_from_stored`/
`external_unit_from_stored` read the *old* snapshot's copy as the merge
fallback for fields those tables do not carry yet (`provenance`,
`hardlinked`, `tool_home`, `relative_path`, `members`, `action`) --
removing the cells silently zeroed that fallback (every unit came back
with `hardlinked: true`/`provenance: BuiltinConvention` regardless of
the real value). Restored those three cells exactly as R16 left them;
only `coverage_json` was actually pure duplication (RootCoverage has no
un-migrated remainder), so only it is gone.
