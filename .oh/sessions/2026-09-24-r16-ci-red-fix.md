## What was red, and why

1. **Linux job** (`crates/cli/tests/linux_collect.rs:83`): the test's
   `observe()` helper looked for a stdout line starting with `"root="`.
   R12's observe/report split (`fe3dbaf`) moved the per-root detail onto
   an indented `"  root=..."` line and put the summary
   (`mode=`/`reason=`/`changed_dirs=`/`walked_total=`) on a line that
   starts `"observed_at=..."`. Fixed the test to match the new prefix.

2. **macOS check-full job**: six `trybuild` compile-fail snapshots
   (`crates/core/tests/compile_fail/*.stderr`) had drifted from the
   pinned-`stable` toolchain's actual rustc diagnostics -- both a real
   API change (R14 made `growth::columns` `pub(crate)` instead of
   private, changing one snapshot's visibility note) and ordinary rustc
   wording drift across two point releases the sandbox's local `stable`
   had fallen behind (1.92.0 vs the 1.98.1 CI/rustup-latest actually
   runs). Regenerated with `TRYBUILD=overwrite` after `rustup update
   stable`; all 37 cases still fail with the same semantic error, only
   wording/path-qualification changed.

3. **Linux release-archive smoke/validation job**: `scripts/release-smoke.sh`

## A fourth bug, only visible once #1 stopped masking it

With the line-83 crash fixed, `linux_collect.rs`'s
`a_collector_makes_observations_incremental_only_while_it_runs` still
failed, deterministically, on a *different* assertion: the second
observe (expected `mode=incremental`) reported
`mode=full reason=no_store` again -- the exact hardcoded fallback text
`cmd_observe` prints in `crates/cli/src/schedule.rs` when it cannot find
a `"fsevents: "`-prefixed note in `Report.notes`.

Root cause: `merge_root_report_into` (`crates/core/src/report.rs`,
present since long before R12) prefixes every per-root note with
`"[{root}] "` before folding it into the merged `Report.notes` --
multi-root disambiguation, nothing to do with observe/report. R12's new
`cmd_observe` summary line is the *only* consumer that reads the merged,
prefixed list with `strip_prefix("fsevents: ")`; every other reader
(`RootCoverage`'s own `mode` field, five different tests) reads a
per-root `Report.notes`, which is never prefixed. `strip_prefix` never
matches a merged note, so every `swamp observe` call, on every
platform, single root or many, has printed the hardcoded fallback text
on its summary line since R12 shipped -- invisible because the fallback
happens to equal the correct answer for a first-ever observation, and
no other test asserted on a *second* call's summary line.

Fixed by searching for the marker instead of requiring it at the
string's start (`n.split_once("fsevents: ")` instead of
`n.strip_prefix("fsevents: ")`), which matches both an unprefixed and a
`"[{root}] "`-prefixed note. Regression test:
`observe_summary_line_reports_the_real_reason_not_the_no_store_fallback`
(`crates/cli/tests/observe.rs`) -- runs on any platform (the bug was
never Linux-specific, only this integration test's assertion on the
second call's fields was), confirmed to fail against the pre-fix code
(`git stash` the one-line fix, rerun, panics on the exact fallback
text), and confirmed to pass with it.
