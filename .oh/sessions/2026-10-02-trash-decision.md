# Trash decisions without the wall of text

## Aim

Let a developer recognize the selected storage, read the few consequences that change their decision, and confirm or cancel without decoding Swamp's implementation.

## Problem Statement

The review repeats internal coverage, adapter, selection and accounting explanations as warnings. Physical-folder inspection also destabilizes navigation, and removed model manifests remain in stored interior rows until refresh. Build modification age is presented as prominent cleanup advice even though it is not last use.

## Solution Space

**Problem:** The decision and its supporting evidence have the same visual priority.
**Key constraint:** Preserve selected paths, source facts, unknown measurements, open-file checks, human protection and confirmation/hold gates; never change a folder move into a manager command.
**Working story:** A short decision summary and an optional evidence view serve different tasks. Recovery, recorded last use and consequential exceptions belong in the summary; bookkeeping belongs in details.
**Success signal:** A normal single build-folder review fits comfortably at 80×24, the model case names the layers staying behind in one sentence, bulk review groups common facts, successful moves disappear immediately and expanding/collapsing a physical layout preserves the selected item and its screen position.
**Decision criteria:** Readability, faithful removal scope, preserved evidence, stable navigation and no new scan work.
**Critical assumptions:** Warning prefixes already generated by core can identify routine explanations; unfamiliar warnings must remain visible. Build modification time cannot be substituted for last use.

### Candidates considered

| Option | Level | Approach | Main trade-off |
|---|---|---|---|
| A | Band-aid | Shorten each warning in place | Keeps every implementation fact on the decision screen; future adapters recreate the wall |
| B | Local optimum | Cap the summary at a fixed number of warnings | Can hide unique data loss, live users or permanent removal; rejected |
| C | Reframe | Summarize decision facts, keep full evidence and paths under `l` | Requires deliberate classification of known routine strings, with visible fallback for unfamiliar facts |
| D | Redesign | Offer semantic model removal rather than manifest Trash | Changes removal scope and authority; deferred because the user selected a manifest |

### Interpretive variety check

A assumes the existing review structure is correct; C tests whether progressive disclosure makes decisions readable. D changes the action itself and would solve storage reclamation, but requires a separately reviewed manager operation. If C still needs pages for a routine action, the hierarchy has failed; reduce routine content rather than cap unknown warnings.

### Recommendation

Selected C, with immediate removal-state and navigation fixes. Accept an extra `l` keypress for audit detail. Preserve all raw evidence for inspection and all removal checks. No new data schema, filesystem walk, manager action or age-derived verdict is needed.

### Execution handoff

- Show a short destination/action total, identifiable targets, recovery/last-use facts and consequential exceptions. Put source/accounting/adapter/selection bookkeeping in optional detail.
- Keep all unrecognized warnings visible; do not implement a generic warning count or length cap.
- Remove generic exact/estimated badges from tables while preserving missing measurements and lower bounds. Keep estimates explained where the figure is specifically an estimate.
- Remove oldest from primary build advice, keep modification labelled in detail, prioritize existing sourced last use.
- Prune successful removed paths from interior state, invalidate derived caches and keep shared payloads intact.
- Preserve selection identity and viewport position through layout expansion/collapse; test the physical layout row's open/closed state.
- Complete focused regressions, a single batched frame review, one correction batch if needed, then the TUI suite and required gates. Update docs, push #218 and install the resulting development build for testing.
