## Implementation and audit decisions

All thirteen views use data-appropriate columns. Projects, Ecosystems and Storage kinds retain measured zero change but omit empty Notes and all-zero bars. Project folders retain hierarchy and show mixed facts under Notes. Build outputs and Dependencies use checkout-relative paths, disambiguate same-leaf checkouts, and keep concise recovery notes at compact widths. Unassigned leads with paths and labels unread/unmeasured values. Reclaim maps typed regeneration classes to short costs while retaining original words and source. Tool storage and Agent storage retain manager routes, model descriptions, inferred associations, protection and exact detail paths. Docker keeps its explicit empty state and permanent-removal language. Disk usage and Coverage gaps distinguish unknown measurements from zero, including child rows and partial rollups.

The key audit covered main list/tree/aggregate navigation, row/group marking, A bulk review, Backspace review/manager routing, section/view keys, all sorting and reverse keys, filter/picker inputs, help, blocked reasons, Cargo inspection, Trash summary/inventory, manager listing/confirmation/results and busy/cancel behavior. Unsupported modifier chords and Repeat/Release cannot invoke plain commands; Shift characters and BackTab remain supported. Raw filter input is literal. The picker project field accepts q/e/0/Space; elsewhere q closes. Fixed-order views ignore sort/reverse and omit those hints. A is described as review all, matching its existing behavior. Manager confirmation names Y, while Enter reviews the manager list. Existing hold, visibility and no-Enter-execution tests remain authoritative.

Independent review found and retired two additional correctness problems: Shift+Enter still passed the first modifier guard, and several Disk Option measurements still looked like zero. The first is now blocked at the terminal adapter; the second is explicitly labelled, with end-to-end table tests rather than only helper tests. Review also flagged repeated checkout-peer comparisons; labels are now computed once per worktree rather than once per artifact. Finer-consequence evidence is indexed once rather than rescanned for every artifact.
